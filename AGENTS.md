# AGENTS.md

## About

`vscode-exts` installs the VS Code extensions declared in TOML manifests into
local, remote (VS Code Server), and WSL-to-Windows editor targets. It is
additive: it never uninstalls anything.

## Layout

- `bin/vscode-exts`: a Python launcher that resolves its own symlink back to
  the checkout and imports the library.
- `lib/vscode_exts/reconciler.py`: all manifest, target-discovery, locking,
  and install logic.
- `share/vscode-exts/schemas/extensions.schema.json`: the manifest schema.
- `examples/extensions.toml`: the starter manifest.
- `docs/design.md`: ownership, aggregation, additive state, locking, and
  packaging decisions.
- `test/vscode-exts-test`, `test/install-test`, and `test/lib/test.sh`.
- `support/install-checkout.sh`: the repo-owned install delegate.

## Invariants

- Python 3.11+ standard library only; no third-party dependencies.
- Never uninstall or touch extensions the manifest doesn't declare.
- A malformed manifest or a missing default configuration exits 2.
  Unavailable editor targets are skipped silently. Gallery, lock, and
  per-extension install failures only warn and keep exit 0.
- When adding a manifest field, update the schema, `examples/extensions.toml`,
  and the README manifest example together.
- The schema's `$id` must start with
  `https://raw.githubusercontent.com/cgraf78/vscode-exts/`.

## Testing

- Local: `test/run`. It runs both suites, compiles an explicit file list
  (`bin/vscode-exts`, `lib/vscode_exts/__init__.py`,
  `lib/vscode_exts/reconciler.py`), validates the schema's `$schema` and
  `$id`, and runs ShellCheck over the inventory's listed programs when
  `shellcheck` is installed. A new Python module must be added to that
  compile list.
- CI: `VSCODE_EXTS_SKIP_SHELLCHECK=1 test/run` on the shared shell matrix
  (Linux distros, macOS, WSL, Termux; profiles `base,python`), plus a separate
  ShellCheck job.
- CI's WSL leg has no Windows-side VS Code, so the WSL-to-Windows path is
  covered only by command fixtures in `vscode-exts-test`. Any change there
  needs a fixture case.

## Test isolation

- Fake editor CLIs go in the suite's `$work/bin`, and fake extension and VS
  Code Server trees under `$work/home`, selected with `--home`. Point
  `XDG_CACHE_HOME` and `XDG_CONFIG_HOME` under the suite root too.
- Never run against real `~/.vscode*` or `~/.vscode-server*` trees, a real
  editor CLI, or the extension gallery.

## CI and generated files

- CI's ShellCheck job fails on any shell program missing from
  `.github/shellcheck-files.txt` (untracked files included) and on stale rows;
  local `test/run` does not detect this. Before pushing, run
  `bash <actions@lock>/.github/actions/shellcheck-inventory/run.sh "$PWD" .github/shellcheck-files.txt`
  from a cgraf78/actions checkout at the SHA in `.github/cgraf78-actions.lock`.
- `install.sh` is generated by the cgraf78/actions checkout installer and
  byte-checked by the `cgraf78/actions sync` job; never hand-edit it. After
  changing `scripts/checkout-installer.conf`, run
  `consumer-ci/sync.sh <this checkout>` from cgraf78/actions at the locked SHA.
- `.github/cgraf78-actions.lock` and every `uses: cgraf78/actions/...@<sha>`
  move together, only via `consumer-ci/sync.sh`.
- `retry-infrastructure.yml` keys on the workflow name `Tests`; don't rename
  it.
